## 🎯 Architecture Pattern

### **Clean Architecture + Feature-First Structure**

Residex follows **Clean Architecture** principles with a **feature-first modular approach**, ensuring:
- ✅ Separation of concerns
- ✅ Testability
- ✅ Scalability
- ✅ Independence from frameworks
- ✅ Role-based feature segregation

```
┌─────────────────────────────────────────────────────────┐
│                    Presentation Layer                    │
│        (UI, Widgets, Screens, State Management)         │
├─────────────────────────────────────────────────────────┤
│                     Domain Layer                         │
│         (Business Logic, Entities, Use Cases)           │
├─────────────────────────────────────────────────────────┤
│                      Data Layer                          │
│    (Repositories, Data Sources, Models, External APIs)  │
└─────────────────────────────────────────────────────────┘
```

## 🎨 Design Patterns

### **1. Repository Pattern**
Abstracts data sources from business logic.

```dart
// Domain layer (abstract contract)
abstract class PropertyRepository {
  Future<List<Property>> getAllProperties();
  Future<Property> getPropertyById(String id);
  Future<void> createProperty(Property property);
}

// Data layer (implementation)
class PropertyRepositoryImpl implements PropertyRepository {
  final PropertyLocalDataSource localDataSource;
  final PropertyRemoteDataSource remoteDataSource;
  
  PropertyRepositoryImpl(this.localDataSource, this.remoteDataSource);
  
  @override
  Future<List<Property>> getAllProperties() async {
    try {
      return await remoteDataSource.fetchProperties();
    } catch (e) {
      return await localDataSource.getCachedProperties();
    }
  }
}
```

### **2. Dependency Injection (DI)**
Using **Riverpod** for compile-time safe DI.

```dart
// core/di/injection.dart
final propertyRepositoryProvider = Provider<PropertyRepository>((ref) {
  final localDS = ref.watch(localDataSourceProvider);
  final remoteDS = ref.watch(remoteDataSourceProvider);
  return PropertyRepositoryImpl(localDS, remoteDS);
});

// Usage in screens
final properties = ref.watch(propertiesProvider);
```

### **3. State Management Pattern**
**Riverpod** for reactive state management.

```dart
// Presentation layer
final propertiesProvider = FutureProvider<List<Property>>((ref) async {
  final repository = ref.watch(propertyRepositoryProvider);
  return await repository.getAllProperties();
});

// In UI
ref.watch(propertiesProvider).when(
  data: (properties) => PropertyList(properties),
  loading: () => LoadingIndicator(),
  error: (e, s) => ErrorMessage(e),
);
```

### **4. Use Case Pattern**
Encapsulates business logic into single-responsibility classes.

```dart
// domain/usecases/get_properties_by_landlord.dart
class GetPropertiesByLandlord {
  final PropertyRepository repository;
  
  GetPropertiesByLandlord(this.repository);
  
  Future<Either<Failure, List<Property>>> call(String landlordId) async {
    try {
      final properties = await repository.getPropertiesByLandlord(landlordId);
      return Right(properties);
    } on ServerException {
      return Left(ServerFailure('Failed to fetch properties'));
    }
  }
}
```

### **5. MVVM (Model-View-ViewModel)**
Separation between UI and business logic.

```dart
// ViewModel (Provider)
class PropertyViewModel extends StateNotifier<PropertyState> {
  final GetPropertiesByLandlord getPropertiesUseCase;
  
  PropertyViewModel(this.getPropertiesUseCase) : super(PropertyInitial());
  
  Future<void> loadProperties(String landlordId) async {
    state = PropertyLoading();
    final result = await getPropertiesUseCase(landlordId);
    result.fold(
      (failure) => state = PropertyError(failure.message),
      (properties) => state = PropertyLoaded(properties),
    );
  }
}

// View (Screen)
class PropertyScreen extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final state = ref.watch(propertyViewModelProvider);
    return state.when(
      initial: () => Text('No data'),
      loading: () => CircularProgressIndicator(),
      loaded: (properties) => PropertyList(properties),
      error: (message) => ErrorMessage(message),
    );
  }
}
```

## 🔧 Core Infrastructure (CRITICAL)

### **1. Dependency Injection (`core/di/injection.dart`)**
**Purpose:** Central registry for all app dependencies.

```dart
// Database
final databaseProvider = Provider<AppDatabase>((ref) => AppDatabase());

// Repositories
final propertyRepoProvider = Provider<PropertyRepository>((ref) {
  final db = ref.watch(databaseProvider);
  return PropertyRepositoryImpl(PropertyLocalDataSource(db));
});

// Use Cases
final getPropertiesProvider = Provider<GetPropertiesByLandlord>((ref) {
  final repo = ref.watch(propertyRepoProvider);
  return GetPropertiesByLandlord(repo);
});
```

**When to use:** ALWAYS inject dependencies through `injection.dart` instead of creating instances directly.

### **2. Navigation (`core/router/app_router.dart`)**
**Purpose:** Type-safe, centralized routing.

```dart
class AppRouter {
  static const String landlordHome = '/landlord';
  static const String tenantHome = '/tenant';
  static const String propertyDetails = '/property/:id';
  
  static Route<dynamic> generateRoute(RouteSettings settings) {
    switch (settings.name) {
      case landlordHome:
        return MaterialPageRoute(builder: (_) => LandlordHomeScreen());
      case propertyDetails:
        final id = settings.arguments as String;
        return MaterialPageRoute(builder: (_) => PropertyDetailsScreen(id));
      default:
        return MaterialPageRoute(builder: (_) => NotFoundScreen());
    }
  }
}
```

### **3. Theme (`core/theme/app_theme.dart`)**
**Purpose:** Consistent UI styling across app.

```dart
class AppTheme {
  static ThemeData get darkTheme => ThemeData(
    brightness: Brightness.dark,

    scaffoldBackgroundColor: AppColors.background,
    // ...

```

### **4. Error Handling (`core/errors/error_handling.dart`)**
**Purpose:** Standardized error responses.

```dart
abstract class Failure {
  final String message;
  const Failure(this.message);
}

class ServerFailure extends Failure {
  const ServerFailure(String message) : super(message);
}

class CacheFailure extends Failure {
  const CacheFailure(String message) : super(message);
}
```

### **5. Constants (`core/utils/app_constants.dart`)**
**Purpose:** Single source of truth for app-wide values.

```dart
class AppConstants {

  static const int minPasswordLength = 8;

```

## 🔄 Data Flow

### **Request Flow Example: Loading Properties**

```
┌─────────────────┐
│  UI Screen      │ → User taps "Load Properties"
│ (Presentation)  │
└────────┬────────┘
         │ ref.watch(propertiesProvider)
         ↓
┌─────────────────┐
│  Provider       │ → State management
│ (Riverpod)      │
└────────┬────────┘
         │ calls use case
         ↓
┌─────────────────┐
│  Use Case       │ → Business logic validation
│ (Domain)        │
└────────┬────────┘
         │ calls repository
         ↓
┌─────────────────┐
│  Repository     │ → Data orchestration
│ (Data)          │
└────────┬────────┘
         │ calls data source
         ↓
┌─────────────────┐
│  Data Source    │ → API/Database call
│ (Data)          │
└────────┬────────┘
         │ returns models
         ↓
┌─────────────────┐
│  Repository     │ → Converts to entities
│                 │
└────────┬────────┘
         │ returns Either<Failure, List<Property>>
         ↓
┌─────────────────┐
│  Provider       │ → Updates state
│                 │
└────────┬────────┘
         │ UI rebuilds
         ↓
┌─────────────────┐
│  UI Screen      │ → Displays properties
│                 │
└─────────────────┘
```

## 📐 Development Principles

### **1. DRY (Don't Repeat Yourself)**
- ✅ Shared widgets in `core/widgets/`
- ✅ Common utilities in `core/utils/`
- ✅ Reusable business logic in `domain/usecases/`

### **2. SOLID Principles**

**S - Single Responsibility**
```dart
// ❌ Bad: Screen does everything
class PropertyScreen {
  void loadProperties() { /* API call */ }
  void saveToCache() { /* DB logic */ }
  void validateInput() { /* validation */ }
}

// ✅ Good: Separated responsibilities
class PropertyScreen { } // Only UI
class PropertyRepository { } // Only data access
class ValidatePropertyInput { } // Only validation
```

**O - Open/Closed**
```dart
// ✅ Open for extension, closed for modification
abstract class PaymentMethod {
  Future<void> processPayment(double amount);
}

class CreditCardPayment extends PaymentMethod { }
class EWalletPayment extends PaymentMethod { }
```

**L - Liskov Substitution**
```dart
// ✅ Can substitute parent with child
PropertyRepository repo = PropertyRepositoryImpl();
// Or mock for testing
PropertyRepository repo = MockPropertyRepository();
```

**I - Interface Segregation**
```dart
// ✅ Small, focused interfaces
abstract class PropertyReader {
  Future<List<Property>> getProperties();
}

abstract class PropertyWriter {
  Future<void> saveProperty(Property property);
}
```

**D - Dependency Inversion**
```dart
// ✅ Depend on abstractions, not concretions
class PropertyViewModel {
  final PropertyRepository repository; // Abstract
  PropertyViewModel(this.repository);
}
```

### **3. Feature Development Checklist**

When developing a new feature (e.g., Bill Splitting):

1. **Create folder structure**
   ```
   features/shared/bills/
   ├── domain/
   │   ├── entities/bill.dart
   │   ├── repositories/bill_repository.dart
   │   └── usecases/split_bill.dart
   ├── data/
   │   ├── datasources/bill_local_datasource.dart
   │   ├── models/bill_model.dart
   │   └── repositories/bill_repository_impl.dart
   └── presentation/
       ├── providers/bills_provider.dart
       ├── screens/bills_screen.dart
       └── widgets/bill_card.dart
   ```

2. **Register dependencies in `core/di/injection.dart`**
   ```dart
   final billRepositoryProvider = Provider<BillRepository>((ref) {
     final db = ref.watch(databaseProvider);
     return BillRepositoryImpl(BillLocalDataSource(db));
   });
   ```

3. **Add routes in `core/router/app_router.dart`**
   ```dart
   case '/bills':
     return MaterialPageRoute(builder: (_) => BillsScreen());
   ```

4. **Use theme from `core/theme/app_theme.dart`**
   ```dart
   color: AppColors.primary,
   textStyle: AppTextStyles.heading,
   ```

5. **Reuse core widgets**
   ```dart
   import 'package:residex_app/core/widgets/loading_overlay.dart';
   ```

## 🎯 Key Takeaways

| Aspect | Implementation |
|--------|----------------|
| **Architecture** | Clean Architecture + Feature-First |
| **State Management** | Riverpod (Provider, StateNotifier) |
| **DI** | Riverpod Providers (`core/di/injection.dart`) |
| **Navigation** | Centralized Router (`core/router/app_router.dart`) |
| **Theming** | Global Theme (`core/theme/app_theme.dart`) |
| **Error Handling** | Failure/Exception pattern (`core/errors/`) |
| **Data Flow** | Repository → Use Case → Provider → UI |
| **Testability** | Mock repositories via DI |
| **Reusability** | Shared widgets in `core/widgets/` |
| **Scalability** | Feature modules isolated from each other |

## 🚀 Moving Forward

**Always remember:**
1. ✅ **Check `core/` first** - Don't reinvent widgets, use shared ones
2. ✅ **Register in DI** - All dependencies go through `injection.dart`
3. ✅ **Follow Clean Architecture** - Domain → Data → Presentation
4. ✅ **DRY principle** - Extract reusable logic to `core/utils/`
5. ✅ **Test early** - Write tests alongside features

**This architecture ensures Residex remains maintainable, scalable, and testable as it grows!** 🎉
