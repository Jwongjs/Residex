# 📋 Residex Top-Down Development Strategy

## 🎯 Development Philosophy

**Build what users SEE first, then connect the backend later.**

This approach:
- ✅ Delivers visual progress immediately
- ✅ Allows early user testing and feedback
- ✅ Reveals actual data requirements organically
- ✅ Prevents over-engineering unused features
- ✅ Maintains team motivation with visible results

---

## 🏗️ Architecture Layers (Build Order)

### 1️⃣ **Presentation Layer** (Week 1-2) - BUILD FIRST
```
lib/features/landlord/presentation/
├── screens/          ← User-facing UI
├── widgets/          ← Feature-specific components
└── providers/        ← State management (mock data)
```

### 2️⃣ **Core Layer** (Parallel to Week 1-2) - CRITICAL FOUNDATION
```
lib/core/
├── widgets/          ← ⚠️ REUSABLE across ALL features
├── theme/            ← ⚠️ Consistent design system
├── router/           ← Navigation management
├── utils/            ← Helper functions
└── constants/        ← App-wide values
```

### 3️⃣ **Domain Layer** (Week 3-4) - BUSINESS LOGIC
```
lib/features/landlord/domain/
├── entities/         ← Pure business objects
├── repositories/     ← Abstract interfaces (contracts)
└── usecases/         ← Business rules
```

### 4️⃣ **Data Layer** (Week 5-6) - IMPLEMENTATION
```
lib/features/landlord/data/
├── models/           ← Data transfer objects
├── repositories/     ← Concrete implementations
└── datasources/      ← Database/API connections
```

### 5️⃣ **Database Layer** (Week 5-6) - PERSISTENCE
```
lib/data/database/
├── app_database.dart ← Drift database
├── tables/           ← Table definitions
└── daos/             ← Data access objects (SQL)
```

### ⚠️ **CRITICAL: Why `lib/core/` Matters**

**Problem Without `lib/core/`:**
```dart

        borderRadius: BorderRadius.circular(32),
        border: Border.all(color: Colors.cyan.withOpacity(0.2)),
      ),
      // ... 50 lines of repeated code
    );
  }
}

class PortfolioScreen {
  Widget build() {
    return Container(
      decoration: BoxDecoration(
        color: Colors.black.withOpacity(0.6), // Same code!
        borderRadius: BorderRadius.circular(32),
        border: Border.all(color: Colors.cyan.withOpacity(0.2)),
      ),
      // ... same 50 lines
    );
  }
}
```

**Solution With `lib/core/`:**
```dart
// ✅ GOOD: Reusable component
// lib/core/widgets/common/glass_card.dart
class GlassCard extends StatelessWidget {
  final Widget child;
  GlassCard({required this.child});
  
  Widget build() => Container(
    decoration: GlassDecoration.card, // Defined once
    child: child,
  );
}

// Now use everywhere

  Widget build() => GlassCard(child: Text('Finance'));

  Widget build() => GlassCard(child: Text('Portfolio'));
```

#### 🎯 Widget Design Principles
1. **Single Responsibility** - One widget, one purpose
2. **Configurable** - Accept parameters, not hardcoded
3. **Reusable** - Works in ANY feature (landlord, tenant, shared)
4. **Themed** - Uses `AppColors` and `AppTextStyles`
5. **Documented** - Clear usage examples in comments

**Example:**
```dart

// lib/features/landlord/domain/entities/property.dart

enum PropertyStatus { occupied, vacant, maintenance }
enum PropertyType { apartment, house, condo, commercial }

/// Pure business object - no database/UI dependencies
class Property {
  final String id;
  final String landlordId;
  final String address;
  final PropertyType type;
  final PropertyStatus status;
  final int totalUnits;
  final int occupiedUnits;
  final double monthlyRent;
  final DateTime createdAt;
  
  Property({
    required this.id,
    required this.landlordId,
    required this.address,
    required this.type,
    required this.status,
    required this.totalUnits,
    required this.occupiedUnits,
    required this.monthlyRent,
    required this.createdAt,
  });
  
  // Business logic methods
  double get occupancyRate => (occupiedUnits / totalUnits) * 100;
  double get potentialRevenue => monthlyRent * totalUnits;
  double get actualRevenue => monthlyRent * occupiedUnits;
  bool get isFullyOccupied => occupiedUnits == totalUnits;
  bool get hasVacancy => occupiedUnits < totalUnits;
}
```

#### Example: Use Case
```dart
// lib/features/landlord/domain/usecases/get_dashboard_stats.dart

class GetDashboardStats {
  final PropertyRepository propertyRepository;
  final FinancialRepository financialRepository;
  final MaintenanceRepository maintenanceRepository;
  
  GetDashboardStats({
    required this.propertyRepository,
    required this.financialRepository,
    required this.maintenanceRepository,
  });
  
  Future<DashboardStats> call(String landlordId) async {
    // Fetch data from multiple sources
    final properties = await propertyRepository.getPropertiesByLandlord(landlordId);
    final revenue = await financialRepository.getProjectedRevenue(landlordId);
    final maintenance = await maintenanceRepository.getActiveRequests(landlordId);
    
    // Apply business logic
    final totalUnits = properties.fold<int>(0, (sum, p) => sum + p.totalUnits);
    final occupiedUnits = properties.fold<int>(0, (sum, p) => sum + p.occupiedUnits);
    final occupancyRate = (occupiedUnits / totalUnits) * 100;
    
    // Calculate system health (custom algorithm)
    final healthScore = _calculateSystemHealth(
      occupancyRate: occupancyRate,
      maintenanceCount: maintenance.length,
      revenueGrowth: revenue.growthRate,
    );
    
    return DashboardStats(
      projectedRevenue: revenue.monthlyTotal,
      revenueChangePercentage: revenue.growthRate,
      systemHealthScore: healthScore,
      activeMaintenance: maintenance.length,
      occupiedUnits: occupiedUnits,
      totalUnits: totalUnits,
    );
  }
  
  int _calculateSystemHealth({
    required double occupancyRate,
    required int maintenanceCount,
    required double revenueGrowth,
  }) {
    // Business logic: Custom health scoring algorithm
    int score = 100;
    
    // Penalize low occupancy
    if (occupancyRate < 75) score -= 20;
    else if (occupancyRate < 90) score -= 10;
    
    // Penalize high maintenance
    if (maintenanceCount > 5) score -= 15;
    else if (maintenanceCount > 2) score -= 5;
    
    // Reward revenue growth
    if (revenueGrowth > 10) score += 5;
    
    return score.clamp(0, 100);
  }
}
```

#### Example: Repository Implementation
```dart
// lib/features/landlord/data/repositories/property_repository_impl.dart

class PropertyRepositoryImpl implements PropertyRepository {
  final AppDatabase database;
  
  PropertyRepositoryImpl(this.database);
  
  @override
  Future<List<Property>> getPropertiesByLandlord(String landlordId) async {
    final results = await database.propertyDao.getByLandlord(landlordId);
    return results.map((data) => data.toEntity()).toList();
  }
  
  @override
  Future<Property> getPropertyById(String propertyId) async {
    final data = await database.propertyDao.getById(int.parse(propertyId));
    return data.toEntity();
  }
  
  @override
  Future<void> addProperty(Property property) async {
    await database.propertyDao.insert(property.toData());
  }
  
  @override
  Future<void> updateProperty(Property property) async {
    await database.propertyDao.update(property.toData());
  }
  
  @override
  Future<void> deleteProperty(String propertyId) async {
    await database.propertyDao.delete(int.parse(propertyId));
  }
  
  @override
  Future<int> getTotalOccupiedUnits(String landlordId) async {
    final properties = await getPropertiesByLandlord(landlordId);
    return properties.fold(0, (sum, p) => sum + p.occupiedUnits);
  }
  
  @override
  Future<double> getTotalMonthlyRevenue(String landlordId) async {
    final properties = await getPropertiesByLandlord(landlordId);
    return properties.fold(0.0, (sum, p) => sum + p.actualRevenue);
  }
}
```

#### Example: DAO (Data Access Object)
```dart
// lib/data/database/daos/property_dao.dart

@DriftAccessor(tables: [Properties])
class PropertyDao extends DatabaseAccessor<AppDatabase> with _$PropertyDaoMixin {
  PropertyDao(AppDatabase db) : super(db);
  
  Future<List<PropertyData>> getByLandlord(String landlordId) {
    return (select(properties)
      ..where((p) => p.landlordId.equals(landlordId)))
      .get();
  }
  
  Future<PropertyData> getById(int id) {
    return (select(properties)
      ..where((p) => p.id.equals(id)))
      .getSingle();
  }
  
  Future<int> insert(PropertyData property) {
    return into(properties).insert(property);
  }
  
  Future<bool> update(PropertyData property) {
    return update(properties).replace(property);
  }
  
  Future<int> delete(int id) {
    return (delete(properties)
      ..where((p) => p.id.equals(id)))
      .go();
  }
}
```

## ⚠️ The Importance of `lib/core/`

### **Why Core Matters:**

#### 1. **Prevents Code Duplication**
```
WITHOUT core/:
- landlord_finance_screen.dart (200 lines of glass card code)
- landlord_portfolio_screen.dart (200 lines of same glass card code)
- tenant_dashboard_screen.dart (200 lines of same glass card code)
TOTAL: 600 lines of duplicate code ❌

WITH core/widgets/common/glass_card.dart:
- glass_card.dart (50 lines)
- Used everywhere with <GlassCard> tag
TOTAL: 50 lines reused 50 times ✅
```

#### 2. **Consistent Design System**
```dart
// WITHOUT core/theme/app_theme.dart
// Finance Screen
Container(color: Color(0xFF06B6D4)) // Cyan?

// Portfolio Screen  
Container(color: Color(0xFF00BCD4)) // Different cyan?

// Community Screen
Container(color: Colors.cyan) // Flutter's cyan?

RESULT: Inconsistent UI ❌

// WITH core/theme/app_theme.dart
Container(color: AppColors.primary) // Always same
RESULT: Consistent brand ✅
```

#### 3. **Single Source of Truth**
```
lib/core/theme/app_theme.dart:
  - All colors defined ONCE
  - All text styles defined ONCE
  - All spacing defined ONCE
  
Change ONE value → Updates EVERYWHERE
```

#### 4. **Cross-Feature Reusability**
```
lib/core/widgets/common/
├── stat_card.dart         ← Used in Landlord & Tenant
├── transaction_card.dart  ← Used in Landlord Finance & Tenant Bills
├── avatar_widget.dart     ← Used in Community & Profile
└── glass_card.dart        ← Used EVERYWHERE

lib/features/landlord/ cannot access lib/features/tenant/
BUT both can access lib/core/ ✅
```

## 🚫 Common Mistakes to Avoid

### ❌ **Mistake 1: Skipping Core Widgets**
```dart
// BAD: Duplicate code in every screen
class FinanceScreen { /* 200 lines of card code */ }
class PortfolioScreen { /* Same 200 lines */ }
```
**Solution:** Always extract reusable widgets to `lib/core/widgets/common/`

### ❌ **Mistake 2: Mixing Layers**
```dart
// BAD: Database code in UI
class FinanceScreen {
  Widget build() {
    final db = AppDatabase();
    final data = db.select(transactions).get(); // ❌
    return Text('$data');
  }
}
```
**Solution:** UI → Provider → Use Case → Repository → Database

### ❌ **Mistake 3: Premature Database**
```dart
// BAD: Building database before knowing requirements
@DataClassName('Transaction')
class Transactions extends Table {
  IntColumn get unknownField1 => integer()(); // What is this?
  IntColumn get unknownField2 => integer()(); // And this?
}
```
**Solution:** Build UI first to discover actual data needs

### ❌ **Mistake 4: No Mock Data**
```dart
// BAD: Empty screens during development
class FinanceScreen {
  Widget build() => Center(child: Text('Coming Soon'));
}
```
**Solution:** Use mock data immediately to build full UI

## 📚 Key Principles

1. **Start Visual** - Build what users see first
2. **Core First** - Extract to `lib/core/` immediately when code repeats
3. **Mock Liberally** - Use fake data until backend is ready
4. **One Layer at a Time** - Don't jump between layers
5. **Test Often** - Run `flutter run` after every widget
6. **Document as You Go** - Add comments explaining complex widgets
7. **DRY (Don't Repeat Yourself)** - If you copy-paste, make it a core widget
8. **YAGNI (You Aren't Gonna Need It)** - Don't build features you haven't designed yet
